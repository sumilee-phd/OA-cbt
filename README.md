# 사무자동화산업기사 필기 CBT

공개 주소: https://sumilee-phd.github.io/OA-cbt/ · 저장소: https://github.com/sumilee-phd/OA-cbt (2026-11-11 공개)

『2027 사무자동화산업기사 1권 필기』의 자체 문항 320개로 만든 필기 CBT 웹앱입니다. 빌드 과정이 없는 정적 파일(HTML·CSS·JS)이라 폴더째 열거나 GitHub Pages에 그대로 올리면 동작합니다.

작성: 2026-11-11. 문항은 전부 저자가 새로 쓴 것이며 공단 공개 문제나 시중 교재 문항을 포함하지 않습니다.

## 문항 구성

| 구분 | 원고 | 문항 수 | 해설 |
|---|---|---|---|
| 필기 모의고사 1~3회 | `20_원고/p05_모의1회.md`~`p05_모의3회.md` | 60 × 3 = 180 | `p06_모의해설.md` |
| 2~8장 대표 문제 | `20_원고/ch02.md`~`ch08.md`의 `## 대표 문제` 절 | 20 × 7 = 140 | `p06_장별해설.md` |
| 합계 | | 320 | 전 문항 해설·근거 절 표기 |

과목은 1과목 사무자동화시스템(2~4장), 2과목 프로그래밍 일반(5~6장), 3과목 네트워크 일반(7~8장)입니다.

## 사용 방법

### 바로 열기

`index.html`을 더블클릭하면 브라우저에서 열립니다. 서버가 필요 없습니다.

### 로컬 서버로 열기

GitHub Pages와 같은 조건(`http://`)으로 확인하려면 이 폴더에서 다음을 실행한 뒤 `http://127.0.0.1:8772/`을 엽니다.

```powershell
python -m http.server 8772 --bind 127.0.0.1
```

ICT폴리텍 저장소의 `.claude/launch.json`에 같은 설정(`oa-cbt`)이 있어 Claude Code 미리보기로도 띄울 수 있습니다.

### 세 가지 모드

| 모드 | 내용 |
|---|---|
| 모의고사 | 회차 선택, 60문항, 제한 시간 1시간 30분. 제출 전에는 정답을 보여 주지 않습니다. 시간이 끝나면 자동 제출합니다. 홈 화면으로 나가도 시간은 계속 흐릅니다(새로고침해도 이어서 풀 수 있음) |
| 장별 연습 | 2~8장 대표 문제 20문항. 문항마다 「정답 확인」으로 바로 채점하고 해설과 근거 절을 보여 줍니다. 시간 제한이 없습니다 |
| 오답 다시 풀기 | 마지막 풀이가 오답인 문항을 모아 장별 연습과 같은 방식으로 풉니다. 전체 또는 과목별로 시작할 수 있습니다 |

합격 판정은 책과 같습니다. 과목별 20문항 가운데 8문항(40점) 미만이면 과락, 과락 없이 전체 36문항(평균 60점) 이상이면 합격입니다. 미응답 문항은 오답으로 채점합니다.

채점 결과 화면에는 과목별 정답 수·점수·판정표와 문항별 해설(선택한 답, 정답, 해설, 「관련 절: 2.1절 표 2-1」 형식의 근거)이 나옵니다. 전체·오답·미응답·정답으로 걸러 볼 수 있고, 「틀린·미응답 문항 다시 풀기」로 그 회차의 틀린 문항만 다시 풀 수 있습니다. 회차별 마지막 결과는 첫 화면 회차 상자의 「결과·해설」로 다시 열 수 있습니다.

오답 목록 규칙은 모든 모드에 공통입니다. 틀리면 목록에 들어가고, 어느 모드에서든 다시 맞히면 빠집니다. 모의고사에서 답을 고르지 않은 문항은 오답 목록에 넣지 않습니다(네트워크관리사 앱 NA2-com과 같은 방식).

단축키: `1`~`4` 답 선택, `←` `→` 문항 이동, `Enter` 정답 확인·다음 문항(연습 모드).

학습 기록은 브라우저 `localStorage`(키 `oa-cbt-v1`)에 저장합니다. 기기·브라우저마다 따로 저장되며 서버로 보내지 않습니다. 홈 화면 맨 아래 「학습 기록 초기화」로 지울 수 있습니다. 문제은행이 바뀌어 없어진 문항 번호가 기록에 남아 있으면 앱이 자동으로 정리합니다.

## 문제은행 다시 만들기

원고(md)를 고친 뒤 이 폴더에서 실행합니다.

```powershell
python build_bank.py
```

스크립트는 원고를 읽기만 하고, 아래 검사를 모두 통과해야 `data/bank.json`과 `data/bank.js`를 씁니다. 하나라도 어긋나면 오류 목록을 출력하고 파일을 쓰지 않습니다(종료 코드 1).

- 회차 60문항(과목별 20), 장별 20문항, 문항 번호 1부터 연속, 보기 ①~④ 4개
- 문제지 정답표(모의고사 끝의 과목별 정답표, 장 끝의 「빠른 정답」 띠)와 해설의 「정답 ①~④」 일치
- 해설 문항 수·번호가 문제와 일치, 해설마다 근거 절 표기(`[2.1절 표 2-1]`) 있음
- 모의고사 문항의 근거 절이 속한 장의 과목과 문항 과목 일치, 장별 문항의 근거 절이 같은 장

```powershell
python build_bank.py --check            # 검사만 하고 기존 파일과 비교(같으면 0, 다르면 2)
python build_bank.py --src D:\원고경로   # 원고 폴더가 ../../20_원고가 아닐 때
```

출력에는 시각 정보를 넣지 않으므로 원고가 같으면 몇 번을 실행해도 바이트 단위로 같은 파일이 나옵니다. `version`은 문항 내용의 SHA-256 앞 12자리입니다.

2026-11-11 실행 결과: 문항 320(모의 180 + 대표 140), 정답 대조 320건, 불일치 0건, version `eab3dc9206ca`.

### 데이터 형식(`bank.json`)

```json
{
  "title": "사무자동화산업기사 필기 CBT",
  "version": "eab3dc9206ca",
  "passRule": { "perSubjectMin": 8, "totalMin": 36, "perSubject": 20, "pointPerQuestion": 5 },
  "subjects": [{ "id": 1, "name": "사무자동화시스템" }],
  "exams": [{ "id": "m1", "no": 1, "title": "필기 모의고사 1회", "minutes": 90, "questionIds": ["m1-01"] }],
  "chapters": [{ "id": "c2", "no": 2, "title": "개발환경과 단말장치 운영", "subject": 1, "questionIds": ["c2-01"] }],
  "questions": [{
    "id": "m1-24", "set": "m1", "number": 24, "subject": 2, "chapter": 5, "section": "5.2",
    "stem": [{ "t": "p", "text": "다음 코드의 출력은?" }, { "t": "code", "text": "int s = 0, i; …" }],
    "choices": ["12", "15", "18", "21"],
    "answer": 1,
    "ref": "5.2절 표 5-5",
    "explanation": [{ "t": "p", "text": "i가 3, 6일 때 continue로 …" }]
  }]
}
```

- `stem`·`explanation`은 블록 목록입니다. `p`(문단), `code`(코드), `table`(`head`·`rows`) 세 종류이며 문단 안의 `` `코드` ``는 화면에서 고정폭 글꼴로 표시합니다.
- `answer`는 1~4, `chapter`는 모의고사 문항이면 근거 절의 장 번호입니다.
- 보기 순서는 책과 같습니다. 해설이 「② 15는 …」처럼 보기 번호로 설명하므로 섞지 않습니다.

## GitHub Pages 배포 절차

2026-11-11 `sumilee-phd/OA-cbt`로 공개했습니다. 아래는 처음 공개할 때의 절차입니다. 같은 방식으로 다른 저장소를 만들 때 참고합니다.

1. 공개 시점을 정합니다. 배포하면 책 출간 전이라도 모의고사·대표 문제와 해설 전문이 공개됩니다.
2. 푸시 계정을 확인합니다. 다른 공개 사이트(NA2-com, ICE-study, pidocs)와 같은 `sumilee-phd` 계정을 씁니다.

   ```powershell
   gh auth switch --user sumilee-phd
   ```

3. 이 폴더만 새 저장소로 만듭니다. 아래 `<저장소이름>`과 `--public`/`--private`는 결정에 맞게 바꿉니다. GitHub Pages는 무료 계정에서 공개 저장소만 지원합니다.

   ```powershell
   cd "U:\2026\전자책출간관련\13_사무자동화산업기사\90_자산\cbt"
   git init -b main
   git add .
   git commit -m "사무자동화산업기사 필기 CBT"
   gh repo create sumilee-phd/<저장소이름> --public --source . --push
   ```

4. GitHub 저장소의 Settings → Pages에서 Source를 「Deploy from a branch」, Branch를 `main` / `/ (root)`로 저장합니다. 명령으로 하려면 다음을 실행합니다.

   ```powershell
   gh api -X POST repos/sumilee-phd/<저장소이름>/pages -f "source[branch]=main" -f "source[path]=/"
   ```

5. 1~2분 뒤 `https://sumilee-phd.github.io/<저장소이름>/`에서 홈 화면, 모의고사 시작·제출, 장별 연습의 정답 확인, 새로고침 뒤 오답 목록 유지를 확인합니다.

이후 원고를 고치면 `python build_bank.py`로 `data/`를 다시 만들고 커밋·푸시합니다. 빌드 단계가 없으므로 GitHub Actions 워크플로는 필요 없습니다. 저장소에는 `build_bank.py`가 들어가지만 원고 폴더는 들어가지 않으므로, 문제은행 재생성은 이 작업장에서 합니다.

## 로컬 확인 기록(2026-11-11)
